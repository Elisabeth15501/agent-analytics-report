# SkillHub 使用示例 · 配套答案

> 本文是 [SkillHub 技能表单](https://open.lenovomm.com)「使用示例」4 个栏位的**配套答案演示**。
> 每条示例包含：用户怎么说 → 技能实际执行什么 → 报告输出示意 → 一句话结论。
>
> ⚠️ **文中所有数字均为示例数据**（用于演示报告形态与洞察逻辑），非真实采集结果。
> 4 条示例共用一套自洽时间线：本周 `08-24~08-30` ⊂ 本月/近30天 `08-01~08-31`，对比为 `8月 vs 7月`。

---

## 示例一 · 生成本周报告，找出最费 token 的任务

**用户说**

> 帮我生成本周 Agent 用量报告，重点看下哪些任务最费 token

**技能执行**

```bash
python scripts/collect_usage_data.py --period week --output data.json
python scripts/generate_report.py data.json --output 本周报告.md
```

**输出示意**

```markdown
# Agent 用量周报

> **报告周期**：2026-08-24 至 2026-08-30
> **报告类型**：周报 · 2026 年第 35 周

## 一、概览统计
| 指标 | 数值 |
|------|------|
| 活跃天数 | 7 天 |
| 会话总数 | 98 个 |
| 总 Token 消耗 | 24.41M |
| 实际花费 | ¥51.33 |
| 失败会话 | 7 个（7.1%） |

## 五、任务类型分布（按 Token 占用排序）
| 任务类型 | 会话数 | Token | 占比 | 平均/次 | 成本 |
|---|---|---|---|---|---|
| 代码重构 | 24 | 9.86M | 40.4% | 411K | ¥20.71 |
| 长文档写作 | 15 | 6.12M | 25.1% | 408K | ¥12.85 |
| 数据分析 | 21 | 4.03M | 16.5% | 192K | ¥8.53 |
| 会议纪要 | 26 | 3.11M | 12.7% | 120K | ¥6.53 |
| 周报生成 | 12 | 1.29M | 5.3% | 107K | ¥2.71 |
```

💡 **回答你的问题**：本周最费 token 的是**代码重构**——只占 24.5% 的会话，却吃掉 40.4% 的 token（9.86M），平均每次 411K，接近周报生成的 4 倍。其次是**长文档写作**（6.12M，25.1%）。两者合计吃掉 65.5% 的 token，要优化就从这两类下手。

## 示例二 · 分析本月成本，找出最贵模型与省钱空间

**用户说**

> 分析本月 AI 调用成本，找出最贵的模型和最省钱的时段

**技能执行**

```bash
python scripts/collect_usage_data.py --period month --output data.json
python scripts/generate_report.py data.json --output 本月成本分析.md
```

**输出示意**

```markdown
# Agent 用量月报 · 成本分析

> **报告周期**：2026-08-01 至 2026-08-31

## 一、概览统计
| 指标 | 数值 |
|------|------|
| 会话总数 | 426 个 |
| 总 Token 消耗 | 112.74M |
| 实际花费 | ¥238.76 |
| 免费调用 | 964 次（未计费） |

## 三、计费维度（按实际计费模型聚合）
| 模型 | 调用次数 | Token | 成本 | 占比 | 有效单价 |
|---|---|---|---|---|---|
| minimax-m3 | 892 | 61.20M | ¥138.20 | 57.9% | ¥2.26/M |
| glm-4.7-flash | 1,406 | 33.80M | ¥62.45 | 26.2% | ¥1.85/M |
| hy3 → 付费执行模型 | 318 | 12.90M | ¥38.11 | 16.0% | ¥2.95/M |
| `:free` / openrouter-free | 964 | 4.84M | ¥0.00 | 0.0% | 免费 |

## 四、省钱机会（按可省金额排序）
| # | 机会 | 预估月省 | 依据 |
|---|---|---|---|
| 1 | 轻任务错配模型 | **¥38** | glm-4.7-flash 的 1,406 次调用中约 61%（858 次）是「会议纪要/周报生成」等低复杂度任务，可切免费通道 |
| 2 | Prompt 缓存复用 | **¥22** | §4.6 显示 18.30M token（16.2%）为重复前缀，缓存命中后可免重复计费 |
| 3 | 批量任务错峰 | **¥19** | 09:00–11:00 集中 34% 的付费调用（¥81.2），为全天最贵时段 |
| | **合计** | **≈¥79（占当前支出 33%）** | |
```

💡 **回答你的问题**：最贵的模型是 **minimax-m3**（¥138.20，占 57.9%），但它承接的也确实是重任务，硬换不划算。真正的省钱空间在**模型错配**（¥38）+**缓存复用**（¥22）——合计约 ¥79/月，占当前支出的 33%，且都不需要牺牲输出质量。

## 示例三 · 扫描 30 天，列出 token 暴增的异常会话

**用户说**

> 扫描最近 30 天，列出 token 突然暴增的异常会话

**技能执行**

```bash
python scripts/collect_usage_data.py --start 2026-08-01 --end 2026-08-31 --output data.json
python scripts/generate_report.py data.json --output 异常扫描.md
```

**输出示意**

```markdown
# 异常检测（2026-08-01 ~ 2026-08-31）

> 本期日均 Token：3.64M

## §4.3 📊 Token 口径（成本之外的独立信号）
| 日期 | Token | 环比前一日 | 判定 |
|---|---|---|---|
| 2026-08-17 | 11.43M | **+315%** | 🔴 峰值 |
| 2026-08-09 | 8.92M | +182% | 🟠 次高 |
| 2026-08-28 | 6.10M | +94% | 🟡 偏高 |

**单次会话 Token Top 3**
| 排名 | 会话 | 任务类型 | Token | 可疑原因 |
|---|---|---|---|---|
| 1 | `a1b2c3d4` | 代码重构 | 1.82M | 含 3 次失败重试，每次重新灌入全量上下文 |
| 2 | `e5f6g7h8` | 长文档写作 | 1.24M | 上下文持续累积，未做分段裁剪 |
| 3 | `i9j0k1l2` | 数据分析 | 0.97M | 重复全表扫描 4 次 |

## §4.3 💰 成本口径
| 日期 | 成本 | 环比前一日 | 判定 |
|---|---|---|---|
| 2026-08-17 | ¥24.18 | +298% | 🔴 峰值 |
| 2026-08-09 | ¥18.86 | +176% | 🟠 次高 |

> 两口径结论一致，08-17 为本期最显著异常日。
```

💡 **回答你的问题**：近 30 天共 3 天 token 异常偏高，最突出的是 **08-17（11.43M，环比 +315%）**。根因不在模型涨价，而在**失败重试重复灌上下文**——Top 1 会话 `a1b2c3d4` 单次 1.82M token，其中 3 次重试各自重传了全量代码。建议对重试做上下文裁剪，预计可压掉这类峰值的 40%+。

## 示例四 · 对比本月与上月，看增长与花费变化

**用户说**

> 对比本月和上月，看看哪些任务增长最快、花费涨了多少

**技能执行**

```bash
python scripts/collect_usage_data.py --period month --compare previous --output data.json
python scripts/generate_report.py data.json --output 月度对比.md
```

**输出示意**

```markdown
# 周期对比（2026-08 vs 2026-07）

## 二、整体对比
| 指标 | 7月 | 8月 | 变化 |
|---|---|---|---|
| 会话总数 | 318 | 426 | **+34.0%** |
| Token 总量 | 86.40M | 112.74M | **+30.5%** |
| 实际花费 | ¥196.72 | ¥238.76 | **+21.4%** |
| 平均单次成本 | ¥0.62 | ¥0.56 | **−9.4%** |

## 五、任务类型增长榜 · Top 5（按 Token 增幅）
| 任务类型 | 7月 Token | 8月 Token | 增幅 |
|---|---|---|---|
| 数据分析 | 9.80M | 21.30M | **+117.3%** |
| 代码重构 | 22.10M | 34.60M | +56.6% |
| 长文档写作 | 14.20M | 18.90M | +33.1% |
| 会议纪要 | 8.60M | 9.10M | +5.8% |
| 周报生成 | 4.10M | 4.30M | +4.9% |
| *（其他长尾类型）* | *27.60M* | *24.54M* | *−11.1%* |

## ⚠️ 数据完整性
本期 6 个无 sessionId 的「幽灵调用」已单列，未计入上表。
```

💡 **回答你的问题**：增长最快的是**数据分析（+117.3%，9.80M → 21.30M）**，其次是代码重构（+56.6%）。花费从 ¥196.72 涨到 ¥238.76（**+21.4%**），但**平均单次成本反而降了 9.4%**（¥0.62 → ¥0.56）——说明这波增长是「用得更多」而不是「用得更贵」，单位效率其实在改善。要注意的是数据分析虽然翻倍，但它平均每次仅 192K token，属于高频轻量场景，规模化是健康的；真正需要盯的仍是代码重构（占 30.7% 的 token）。
